## 3. Things that went wrong, and the corrected facts (read before trusting any number)

* **Spike H round 3.** PR1 (byte-compat of old outputs) fails by design: the `db_unchecked` notes lines change the notes of every
  fixture. Two cells (`m_cancel_sneaky`, `m_items_zero_to_latest`) are known unfixed library gaps (path-parameter bounds produce no
  at/beyond case; an `unchanged` check with no baseline row is dropped with only a note).
* **Spike I round 4 was never scored.** Cause: (a) my staging copy (symlink) broke the loader; (b) the frozen round-2 runner chain
  turns `FailedPrecondition` into `FAILEDPRECONDITION`, not a valid gRPC code, so the truth-flow replay crashes (10 scenarios);
  (c) the contract check and round 2's `_truth_replay` ignore `links`, so FLOWS is "not scorable" for any link-bearing truth;
  (d) the harness `build_db(path)` of the held-out had no `return`, so `make_app(None)` created a database called `None` and every
  login failed (this was a gap in `HARNESS_API.md`, my document, as was the missing `process_runtime`). The run ledger is per
  `--out` directory, so the run count is only auditable by listing out directories.
* **Spike I round 3** (merged) was **not a clean blind held-out**: its author read the prereg and ran before the freeze; the runner
  was changed twice after the freeze and its self-hash check disabled once. Use the verifier's corrected counts (2 of 8), not the
  runner's.
* **Spike I round 4 changed behaviour on purpose:** a never-registered service beside an unresolved registration now reads `unread`
  (D1.3). Four round-3 tests were updated for it (`tests/grpc/test_wiring3.py`). `goextract_grpc.go` is 749 lines against a
  400-line budget (budget missed); D3.4 (error types with a `GRPCStatus()` method) is not built.
* **J1 round 2 mutant tally.** The mutant runner crashed once before any metric (the S3 `studio.toml` names a bare module that the
  runner's in-process setup cannot import; S2 uses the dotted form, so the stand-in test missed it) and the permitted re-run used
  `PYTHONPATH` (an environment change, no byte change). The runner counts 32/35 killed; the independent verifier says that under a
  strict reading it is 30/35. PI4-3 and PR3-3 hit the same crash in the single scored probe run and cannot be re-run: their
  substance is untested. `goextract_closure.go` is 102 lines against 80 (budget missed). Survivors: JM6 (design limit),
  JM31 (library false negative: layer R sees it, layer A does not), JM34 (its 409 item is unreachable by probe).
* **Process defect (mine):** the J1 round-2 runners were frozen with a hard-coded NOT RUN for S3; the S3 runners were then written
  by a builder blind to the fixture (Amendments 5-6).
* **Known baseline failures on `next-phases` (not caused by this work):** 7 importer tests (`test_import_token_answers.py::...[in_dependency|in_helper]`,
  `test_mine.py::test_multivendor_recall_and_precision`, four in `test_policy.py`), about 96 collection errors from missing DB
  drivers and `bench/template_app` (`NameError: Item`), and a few timing-flaky studio tests

## 4. The direction, honestly

replay, change impact (observed and determined tiers), the app map, rationale and glossary, and (now) Layers R and B on Go.

rpcs; the safe answer is "unread/unclear", never a confident wrong one); **nothing has been run end to end on a real app in this
container** (Streak, MySQL, Docker); H and I never met their gates. The recommended next order is Go first, then gRPC, then .NET.

## 6. How the work was run (reuse it)

* **House protocol:** pre-registration (opus: blind predictions with ranges, numeric pass rules, >= 8 mutants, risks) -> orchestrator
  rulings as an Amendment -> build node (sonnet, own git worktree, never commits) -> freeze hashes of changed library files and
  runner **before** any gated probe -> a **separate** author writes the frozen set / held-out **after** the freeze (fixed working
  directory; the orchestrator audits its tool calls from the transcript) -> a contract check -> scored **once** -> an independent
  opus re-run -> results doc with blind and post hoc rows separate -> merge only on the owner's yes. Max 4 agents in parallel.
* **Lessons:** put every harness-API fact the author needs in the brief (the omissions cost a round each); make the runner and the
  scorer complete (including every arm) before the freeze; never disable the runner's self-hash check; the run ledger must be global;
  do not name the idioms you want tested in the author's brief; an unquoted shell heredoc eats backticks in prereg amendments (use
  `<<'E'`).
* **Commands:** `uv run python -m pytest tests/<dir>` (set `UV_NO_SYNC=1 PYTHONDONTWRITEBYTECODE=1`); `go` is at
  `/usr/local/go/bin/go` and the module proxy works; commit with explicit paths only (never `git add -A`); no Anthropic API key is
  used anywhere, model use is through the `claude` CLI only; agents never commit and nothing merges without the owner's yes.
* Worktrees used this session lived under `/home/user/wt/` in the container and are gone with it; every branch above is pushed.

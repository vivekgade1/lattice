## 1. Where things stand

| Question | Answer | Evidence |
|---|---|---|
| Is Lattice, as the language an LLM edits in, safer than editing Python? | **No**, on CRUD tickets (confirmation run) and on this app. The language cannot express common response shapes (§3). | results log, "Confirmation run"; option-1 spec §"Why arm L is not in this experiment" |
| Does a Lattice guarantee, **checked on ordinary Python**, prevent silent bugs a frontier model makes? | **Yes, for partial writes, on Sonnet (pre-registered).** Silent runs 18 → 8, correct runs 24 → 34, partial-write silent runs 17 → 0 (Fisher p = 0.016). **Haiku:** not confirmed overall (p = 0.087), but partial writes 14 → 0. | results log, "Option 1 main experiment"; `ace4e96` |
| Where do frontier models slip? | **Not** on aggregation traps (fan-out, nulls, empty groups, date boundaries; 12/12 in the pilot) and **not** on ownership. **Yes** on atomicity: reusing a helper that commits partway, so a refused request leaves partial writes (8/9 runs on t38–t40 with a committing helper, 0/12 on t41–t44 without one). | results log, "Option 1 pilot", "Option 1b" |

**What this means for direction.** The only confirmed value on a strong model is *the
checker on ordinary Python*. That points to repositioning Lattice as a checker and
verified-edit loop, with the language and IR kept internal. The user has **not chosen**
yet. The open options are in §6.

## 2. Standing rules (the user's)

- **No API key, ever.** Every model call goes through the Claude CLI (`--backend cli`,
  `lattice/llm/cli_client.py`, billed to the user's plan). This is enforced in code:
  `ClaudeGenerator` raises `ApiKeyTransportDisabled`, the runner and importer accept only
  `--backend cli`, and `--estimate` counts tokens by characters. See memory `no-api-key`.
- **Pre-register.** Commit a spec with the hypotheses, tests and decision rule before any
  model run. Apply the rule mechanically (`bench/edit_slice/pilot_gate.py`,
  `bench/edit_slice/main_analysis.py`).
- **Oracle rule.** Never compare what a ticket's text does not determine. After every run,
  read each silent run's saved code (re-run the final candidate, read the diff). A case the
  text doesn't determine is excluded, all arms are rescored without new model calls
  (`bench/edit_slice/rescore.py`), and both verdicts are reported. Four such cases were
  found in option 1 (see `STATUS_ONLY` / `EXCLUDED` in `bench/edit_slice/repos/multivendor.py`).
- **Ask before starting a new experiment or language sub-project.** The user approves
  ticket texts before any oracle work, and designs before building.
- **Report** tokens, cost per correct run, repair rounds, time per run, lines changed,
  and Wilson intervals. Send a push notification when a long run finishes.

## 4. Known limitations found (not fixed)

1. **Responses are flat.** An endpoint cannot return an object containing a list (an order
   with its `items`, a vendor with its `products`). T2 values of such types cannot cross
   into a response (L883). This alone made arm L unusable on 5 of 7 atomicity tickets.
2. **L802 with non-admin roles.** Under `Roles(...)`, only the admin may read other users'
   rows (for example, "a vendor updates any order's status" is refused).
3. **`owner_via` is not inferred** for "product owned through vendor" or "order line
   through order".
4. **The importer on this app:** 3 of 17 routes verified. The $6 budget ran out; three
   routes were cut off at the output cap; `place_order`'s list-of-objects body is
   unsupported; bare-list responses are not lifted.
5. **pycheck's PY801 is not applied to `Roles`/`Authenticated` routes.** Widening it
   produced false findings on correct code (a public catalogue; a vendor closing a shop
   legitimately touches other buyers' orders), so it was reverted.
6. **pycheck is syntactic.** PY807 cannot see failures raised by the database or a
   library, or helpers more than three calls deep.

## 5. The Go target (merged into `develop`)

`go-target` (87 commits, another session) adds a Go target and the binding
**language rules** (`docs/lattice-language-rules.md`, R1–R14): no lowest-common-
denominator drift; every construct must be implemented on every target or be explicitly
gated. The role-set constructs from `64d7ebe` are gated on Go (decision-log entry
2026-09-30) until Go implements them. See that doc before any language change.

## 6. Open decisions for the user

1. **Reposition around the checker.** pycheck plus a verified-edit loop on ordinary code,
   with Lattice's IR internal: the direction the evidence supports.
2. **Widen PY807's evidence first.** More apps, more atomicity patterns, other models, to
   check the Sonnet result is not specific to these 7 tickets.
3. **Nested responses in the language**, then retest Lattice as an editing language (arm L).
   A sub-project with weaker evidence behind it.

## 7. How to run things

```sh
uv run pytest -q                                            # the full suite (~30 min)
uv run python -m bench.edit_slice.run --backend cli --model claude-sonnet-5 --arm P|Q|L \
  --tickets option1|option1b|t38_reorder,... --reps N --workers 4 --out bench/results/X.jsonl [--resume] [--estimate]
uv run python -m bench.edit_slice.pilot_gate RESULTS.jsonl [--pilot 2]
uv run python -m bench.edit_slice.main_analysis RESULTS.jsonl ...
uv run python -m bench.edit_slice.rescore RESULTS.jsonl --tickets ... --out RESCORED.jsonl
uv run python -m lattice.importer . --package <pkg>.app --app-factory <mod>:make_app \
  --out DIR --backend cli [--no-llm] [--dialect sqlite] [--max-cost-usd X]
```

Run records and artefacts are in `bench/results/` (gitignored). The option-1 files are
named `option1_pilot_*`, `option1b_pilot_*` and `option1_main_*`.

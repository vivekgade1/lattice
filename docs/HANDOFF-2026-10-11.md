## Configure a project for the fast path (`studio.toml [rebuild]`)

```toml
scoped_gate_args = ["--layers", "CD", "--x-repeats", "1", "--await-cap", "5"]  # off if absent
level_gate = "regression"      # or "full" (default)
level_gate_args = ["--x-repeats", "2"]  # regression level gates only; ~62 s less per level on Streak
level_repair_attempts = 2      # 0: a failing level stops the plan as in v1.10
node_timeout = 1800            # seconds of one node's agent step; usage is kept on a timeout
sync_spec = "off"              # "auto": sync the committed spec onto the target before a run
```
The first gate command must forward `"$@"` last (Streak's `check.sh` does).

## Things that are not obvious

- **Builds use the spec committed on the build branch.** A spec fix on a working copy is
  invisible to nodes: commit it on the spec branch, then `POST /api/branches/{name}/sync-spec`
  (or `sync_spec = "auto"`, or the "Sync spec" banner) puts the spec files on the build
  branch (done by hand for Streak: `main` a0db033, `build/streak` a0679e9).
- **A gave-up agent that says "this check can't pass" is usually right.** Both of p2's stops
  were unsatisfiable `expect_db` preconditions in the spec. Verify with a control (original
  spec fails at the named step, fixed spec passes) before changing the spec.
- **A Studio change set drafts requirement text.** It cannot make a scenario-only fix (c1 added
  a rule that locked the bug in). Edit `spec.py` directly (owner's decision), commit, merge.
- **Per-tip results** live in `<state dir>/results/<commit>.json`, keyed by commit and gate
  commands; a merge commit has none, so the first start baseline after a spec merge runs a
  full gate (~150 s on a built Streak tip, 416 s on a cold one).
- **The level gate's layer X (~117 s) does not shrink** with the regression selection.
- **Server prose levels are 0-based**; the UI shifts "level N" by +1 (`serverLevels` in `plan.js`).
- A **kept worktree** `streak/.lattice/rebuilds/streak-b4-a93dcb` (`rebuild/p2-account`, the
  gave-up first attempt) can be removed with `git worktree remove --force`.

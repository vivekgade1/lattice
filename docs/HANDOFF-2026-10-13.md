## 2. What is built (layer 3)

- `lattice/contracts/` (`export.py`, `check.py`, `live.py`, `__main__.py`): a provider's export is
  derived from its spec (in a subprocess); a consumer lists its reliances in
  `lattice.imports.toml` and pins the export into `lattice.contracts.lock.json`; `check` classifies
  each claim BROKEN (held by the pin, not now), GAP (never in the spec) or CHANGED (any other diff
  item, tagged `relied`). Opt-in per link: `[[link]] contract = "static" | "live"`.
- Live (`contract = "live"`): replays the provider's own spec steps against its app on a
  throwaway SQLite database it starts itself; any `live_url` is refused.
- Surfaces: CLI `lattice contracts export|pin|check`; MCP `contract_check {consumer?}` (with a
  workspace only, read-only); Studio `GET /api/contracts[?consumer=NAME]` (API v1.17, static only,
  mocked); dogfood rule R94 with one scenario; no web UI change.
- Evidence: 35/35 probes, 0 prediction misses (incl. the predicted misses D7, D10 and the
  under-classified D8), 11/11 mutants, on ONE pair (job-scheduler + `ci-bot`).

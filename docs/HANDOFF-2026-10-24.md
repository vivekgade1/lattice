## 4. The harness question (research done 2026-10-24; condensed)
**Question:** should Lattice become an agentic harness (own the agent loop)? **Answer: no. Stay a spec and verification layer that wraps someone else's loop ("rent the loop, own the verdict")**, owning the frame (worktree, protected spec and gates run by Lattice, round and cost caps, ledger) and keeping only small single-purpose generate-check-repair loops where a deterministic checker returns exact errors.
Why (five researchers: harness literature, verifier-loop evidence, ecosystem, extraction generalisation, Lattice's own repo):
- **Harness literature:** large same-model spreads come from company blogs and unverified summaries; the one controlled study (single-author preprint) found no average winner (48.8% vs 50.0%, interval [-10, +7.5]); Anthropic says harness components go stale as models improve (context resets became "dead weight" on Opus 4.5); Manus rebuilt its framework four times in under a year.
- **Verifier literature:** every mitigation that works removes the agent's access to the oracle (read-only tests, an abort option cut GPT-5 cheating 54% -> 9%, sealed git history, scoped re-rendering of editable slots, clean-checkout re-runs); none depends on who runs the turns. Weak verifiers inflate results (15.7% of SWE-bench Verified passing patches were wrong; METR: maintainers would merge about 24 points fewer).
- **Ecosystem:** plug-in verifiers converge on a plugin bundle (MCP + hooks + skills) plus a CLI fallback (Semgrep, Snyk, Sonar); independent verification layers are still funded (CodeRabbit, Qodo); loop-owning retreats were IDE agents (Sourcegraph Cody, Roo Code, Aider). Platform risk: Anthropic closed subscription OAuth to third-party harnesses in 2026, headless billing churned, Agent SDK terms require API-key auth.
- **Extraction:** static extractors are framework-bound (H2 is this class); LLM-agent exploration alone does badly (85% false discovery on project-scale tasks); the best evidence is hybrids that send an LLM only the residue a static pass could not resolve and accept a fact only on confirmation (SemTaint). **No study covers ASP.NET Core or EF Core; no validated unfamiliar-idiom detector exists.**
- **Lattice's own record:** Lattice owns no model loop (every call is `claude -p`; API-key transport disabled in code); the failures logged sit in the extractor, spec, scorer and tool surface, and H2's causes are in deterministic static analysis; but **no row ever varied loop ownership**, and the real-agent rows are toy fixtures or n=1.
**Caveat that matters most:** no source, inside or outside the repo, measures whether a verifier that owns the loop beats one called by a foreign agent. The recommendation is a reasoned default with a priced experiment attached (step 4 below, about USD 3-15), not a finding. Evidence quality is mixed (secondary sources, preprints, unverified Terminal-Bench figures were left out of the report).
**Declared gaps in the frame Lattice already owns** (from the repo): the Studio rebuild argv carries no `--max-turns` or `--max-budget-usd` (only `dogfood/` shims and `implement --usd-cap` do); `node_max_tokens` counts output tokens only (an earlier run understated cost about 75x by ignoring cache tokens); the guard hook is "not a sandbox" and `acceptEdits` allows `rm`/`mv`/`cp` in the worktree; prompt-injection fencing (WP1) and context management (Spike CM) are not started.
**What would change the call:** the owned loop wins step 4 for a reason only an owner can supply (sealed oracle, abort path); the plugin path leaks at a non-trivial rate; a bounded resolver improves recall on a fresh app without losing determinism; Anthropic changes `claude -p` terms so the CLI-only rule cannot hold; a customer needs the verdict in CI without Claude Code; a platform vendor ships the same spec check.
